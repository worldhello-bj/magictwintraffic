# 合成高需求演示：车辆数量与范围解释

这是独立的、未经现场标定的演示情景，不是成都实测流量，也不加入既有 340 场研究结果或政策排名。

## 为什么旧开场只有约 100 辆

旧默认 600 秒机制回放从空路网开始，只有 16 个入口、名义每入口 120 辆/小时，420 秒后停止到达。S0 全程总共生成 231 辆；5 秒采样的全网瞬时数量平均 102.7、峰值 151，严格 1 × 1 km 核心内平均 34.3、峰值 55。全程生成数、每小时到达率、屏幕当前在网数是三个不同量。旧开场还包含建立交通状态的过程，不能当作已达到高峰的街区。

## 新演示配置

- 实际 SUMO/libsumo 1.28.0，原真实 OSM 路网，无复制车辆、渲染层补车或瞬移。
- `scenarios/dense_demo.json`：seed 42，S0/S7 共用同一个外生车辆清单；名义每入口 360 辆/小时。现有 AM 方向系数与每 5 分钟脉冲仍适用，并非所有入口恒定相同流量。
- 总仿真 1,800 秒，前 600 秒预热，需求持续至 1,500 秒，后 300 秒继续运行观察消散；默认回放从真实仿真 t=600 秒开始，也可回看预热。
- 共生成 2,651 辆，包含 20 辆固定合成公交；其中预热期 1,015 辆，之后目标评价队列 1,636 辆。25 分钟总到达量折算约 6,362 辆/小时，是全网 16 个入口合计，不能解释为每条路或核心区流率。Poisson 模型预期小汽车数约 2,633；实际小汽车数为 2,631。
- 使用边界入口到出口的合法路径，途经核心与外围。尚无内部地块起终点需求，因此不声称每条住宅支路都具有真实使用强度。
- 物理积分与保存间隔均为 0.5 秒；每个保存帧包括所有实际在网车辆。播放倍率改变观看速度，不改变物理运行时间和指标。

## 实际结果

以下均来自 `docs/evidence/dense_demo.json`，瞬时数量均使用全部车辆队列，活跃窗口为 t=600–1,500 秒，按 5 秒记录统计。

| 量 | S0 | S7 |
| --- | ---: | ---: |
| 开场 t=600 全网在网 | 595 | 611 |
| 开场严格 1 km² 核心内 | 154 | 158 |
| 开场外围在网 | 441 | 453 |
| 活跃期全网平均 / 峰值 | 775.3 / 854 | 782.8 / 869 |
| 活跃期核心平均 / 峰值 | 196.6 / 235 | 204.0 / 237 |
| 活跃期外围平均 / 峰值 | 578.6 / 671 | 578.7 / 668 |
| 活跃期边界外等待平均 / 峰值 | 148.4 / 246 | 167.3 / 255 |
| 1,800 秒已完成（所有队列） | 1,869 | 1,825 |
| 1,800 秒仍在网（所有队列） | 572 | 577 |
| 1,800 秒仍在边界外等待（所有队列） | 210 | 249 |
| 目标队列 TSTT（车·秒） | 823,062.178 | 832,947.178 |

S7 的目标队列有限窗口 TSTT 比 S0 高约 1.20%，没有显示全面改善。两者均仍有未完成行程，300 秒消散期不代表已经清空；完成车辆的平均旅行时间不是全需求收益。场景用于观察真实运行中的排队、边界接收、核心和外围差异，不用于证明组合政策优胜。

逐步车辆守恒均通过，碰撞数与瞬移数均为 0；SUMO 禁止超时瞬移和超时丢弃待插入车辆。边界外等待保留并计入目标队列 TSTT，但不画成已经在道路上的车。S0 满足 2,651 = 1,869 + 572 + 210，S7 满足 2,651 = 1,825 + 577 + 249。

## 显示与评价队列

原 `timeseries.inside/core_vehicles/periphery_vehicles/external_waiting` 专用于预热后目标评价队列。为避免预热车辆在画面中存在、数字却为零，新导出另提供 `all_cohort_inside/all_cohort_core_vehicles/all_cohort_periphery_vehicles/all_cohort_external_waiting` 用于当前场景占用显示。原目标队列指标算法不变，历史正式证据文件未改动。

## 复算

```sh
.venv/bin/python scripts/run_dense_demo.py
```

首次 `npm run dev` / `npm run build` / `npm test` 会通过 `scripts/ensure_dense_demo.py` 检查默认回放：已有完整轨迹会做校验后直接复用，已有完成的原始运行仅重新打包，仅缺少的政策才重新模拟。需要先安装锁定 Python 依赖（包含 SUMO/libsumo）；Python 脚本优先使用仓库 `.venv/bin/python`，否则使用当前 Python。首次配对模拟在本次云端实测约 40 秒，具体电脑可能需更久；之后可离线复用。前端资产测试也会确保完整回放存在，缓存已生成时仅校验复用；后端单元测试无需预先生成演示。损坏或配置不匹配的已完成原始结果会明确报错，绝不静默覆盖；未完成的失败目录会先保留再重试。

显式运行上述命令会生成两个独立 `runs/dense_demo_S{0,7}_am_42_v1` 目录、检查审计与相同需求哈希，并将它们置于回放目录最前。已完成目录不会静默覆盖；仅重新打包已完成、配置匹配的运行使用 `--package-only`。仓库携带旧 600 秒 S0/S7 记录、可复算场景、生成器与结果证据；约 62 MiB 的新完整轨迹不存入 Git。首次 npm dev/build/test 自动生成并打包缺少的新记录，默认目录生成后共四个代表性回放；在线版还保留此前另外七个已公开记录（其余六个政策和 9,900 秒参考），新增之后共十一条，不移除旧线上演示。正式研究数据、配置和结果保持独立。
