# 玉林高压拥堵与恢复实验（合成情景，非现场校准）

## 目的与冻结边界

本组实验回答“当外部到达与建筑出发共同超过局部通行能力时，真实微观车辆如何积压、向上游延伸，以及政策是否会更差”。不增加纯视觉车辆、不强制安全插入、不瞬移、不删除未完成行程。已有正式研究和适度演示均保留。

最终发布网络为 `joined_north_surface_v3`：先修复已确认的倪家桥0.20m双路口互锁，恢复OSM两条明确motor_vehicle=yes道路的车行权限，再合并北侧34m×26m范围内7个地面路口节点，移除9段被合并的外部连接并重建交叉冲突与实验信号。保留旧可达掉头，passenger和bus的收缩后进出动作无新增、无缺失。33条立交/隧道相关道路的几何与权限完全不变，不把隧道并入地面路口。信号仍为未现场核实的仿真配时。`*_v1`、`*_v2`保留为前期诊断，不能替代最终v3政策表。

## 需求与观察窗

- `scenarios/high_pressure_v3.json`：入口基准强度 360 辆/小时/入口，叠加已公开的 AM/PM 方向系数、5分钟脉冲和泊松到达；因此不是每个入口恒定360辆/小时。
- 建筑片区初始停车按每栋3辆、每区20–100辆估计；70%存量申请出发，3%存量在t=0申请出发，其他按早晚三角分布释放。这是可复现假设，未测量停车容量或人口。
- 内部目的地比例30%；边界车辆改内部目的地时沿用原车辆身份，不复制流量。合法车道容纳不下时持续记录插入等待。
- 需求0–1800s；预热0–300s；评价目标为300s以后出发的peak群组。总模拟4200s，包含2400s撤压恢复尾段。
- S0/S7各自AM/PM用42、43、44三个种子；同一时段和种子的政策对照必须拥有完全相同需求哈希和网络哈希。
- `moderate_matched_S0_am_42_v3` 保留原适度160强度及较少库存/释放，同样1800s需求与4200s观察窗。它用于强度比较，不是同OD政策实验。
- `recovery_pressure_S0_am_42_v3` 采用300强度、其他参数同高压。是否恢复由真实运行结果决定，名称不保证每个种子/网络一定清空。

## 度量与限制

`docs/evidence/high_pressure_demo.json` / `.csv` 保存最终12运行、政策配对差异、安全/守恒审计；`high_pressure_comparators.json`保存两种同窗对照；`high_pressure_ladder.json` / `.csv`保留全部前期网络探针，包括持续停滞结果，不选择性抹除。

每条运行的 `high_pressure_analysis.json` 包含：

- 600–1800s同一负荷观察窗的在网、核心、外围、等待与停止车辆均值/峰值；完整轨迹中的严格1km²核心停止峰值。
- 每5s采样的车辆帧算术平均速度（公里/小时），并非行程调和平均意义的space-mean speed；历史字段名中space_mean不能改变此定义。
- 已完成peak车辆的“实际耗时减自由流参照”平均延误；未完成行程单独保留，主指标是含等待和未完成的有限窗TSTT，不以已完成平均掩盖积压。
- 实际停止链的道路存储压力代理：同车道至少4辆速度<0.1m/s；队尾离上游端≤20m；队首到达至少70%车道长度；相邻车头位置间距≤20m。最长连续时长按5s采样统计。该代理可核查上游排队延伸，但不自动证明路口已被阻塞。
- 需求截止后第一次“在网=0且到时未插入=0”的时刻；没有满足则记录null并完整报告末尾存量。
- 每300s实际长等待车辆的车道、位置、同车道前车、下一个信号、路线与停止状态，位于 `long_wait_snapshots.json`，用于区分红灯、多周期滞留、空间闭环和模型问题。

队列计数含所有群组；speed<0.1m/s计数不等于连续排队米数。轨迹位置只包含实际SUMO车辆，不含停车库存。初始停车+边界插入=当前停车+道路车辆+边界完成，另有已到时需求=未插入+道路车辆+完成，逐步校验，两者不能混为同一口径。

## 重现与发布

```sh
python scripts/restore_assets.py
.venv/bin/python scripts/build_internal_network.py
.venv/bin/python scripts/build_access_network.py
.venv/bin/python scripts/build_north_surface_network.py
.venv/bin/python scripts/run_high_pressure_demo.py --seeds 42,43,44
.venv/bin/python scripts/run_pressure_comparators.py
.venv/bin/python scripts/run_pressure_ladder.py
```

网站只发布seed42的四个高压政策/时段回放和可选对照，不要求每次npm执行重复种子。`ensure_high_pressure_demo.py`验证配置、网络内容哈希、轨迹校验和、安全/守恒与同OD配对。缺失时仅重建所需网络与seed42；已有但配置或网络不同的完成运行拒绝覆盖。默认从t=1200s展示实际高压状态，用户可从t=0查看全过程。

每个发布轨迹是0.5s原始状态的1s精确抽样；它不改变物理、评价或车辆数量。不要用不同观察时长的旧1800s演示与新4200s实验直接比较总TSTT或完成率。负荷加大导致模型停滞并不自动证明成都现实存在永久死锁；源拓扑、进口权限、未建模行为和实验配时都应保留在结论限制中。


## 北侧拓扑反事实

`docs/evidence/north_surface_counterfactual.json`对比完全相同4042个行程的v2与最终v3，车辆ID、出发时刻、起终点、行为种子完全一致。v2到4200s完成2916、在网700、等待426；v3完成3984、在网58、等待0，最后600s仍有129辆完成。v3峰值仍有1283辆在网、严格核心519辆、859辆停止，未通过削弱流量掩盖拥堵。它属于网络建模反事实，不属于同网政策收益实验。

最终v3没有删除车辆、干预车道状态或关闭安全约束。审计中的单车移除仅发生于另存的诊断状态，用于识别阻挡关系；从未用于正式轨迹或上述反事实两条运行。

## 最终v3结果摘要（12次运行已冻结）

所有正式运行与两条同窗对照均使用网络哈希 `852d34522be4f77627849a30201cc92eb0d6d0208466302f26c9f9d90dc21b19`。12次正式运行的碰撞、瞬移和两类守恒残差均为0。默认早峰S0在负荷窗内道路车辆峰值1283、核心峰值519，全窗停止峰值859；同窗适度基准分别为420、188、170。早峰S0末尾仍有58辆，属于观察窗内尚未完成，不能删除或声称已完全清空。

S7相对S0的peak群组有限窗TSTT变化：

- 早峰种子42、43、44分别为 +39.78%、+40.90%、+6.65%。
- 晚峰分别为 +4.36%、+11.75%、+27.17%。

本次六组同OD对照均未改善该总耗时指标；只有三个种子，不宣称统计显著或现场因果结论。早峰种子44的S7多完成59辆但TSTT仍更高，说明不能只用完成数或已完成平均耗时选政策。

S7早峰种子42在玉林街/玉林南街与倪家桥路的单一信号节点432452987留下持续模型网格锁死。此处外部道路长38.77–177.88m，没有前述0.20m短连接，信号仍切换。内部路口车辆相互让行的潜在冲突与S7只检查出口车道、不检查内部路口占用的绿灯延长条件有关；这是有边界的模型诊断，尚非逐车因果或现实道路验证。不再为使S7“好看”而修改信号、删除车辆或继续调整网络。改善内部路口接收空间判断应另立后续实验。

同窗160强度对照全部1827行程于2465s前完成；300强度对照全部3516行程于4050s前完成。对照证明高密度排队和长恢复过程可以在撤压后消散，而正式360强度观察窗未强制延长到每条运行清空。
