# 玉林建筑活动、初始存量、OD 与真实信号回放

本功能是新的、未校准的演示场景，不替换已归档的正式研究，不将新演示的 S0/S7 差异称为经验证的政策收益。

## 数据与假设

- 玉林核心区真实 OSM 建筑轮廓按 250m 网格汇总为 16 个活动片区。
- 片区初始停车数量是假设：默认适度演示每栋建筑 2 辆、每片区下限 20 上限 100，合计 836 辆；旧网络压力诊断使用每栋 3 辆、合计 1187 辆。这不是人口、停车容量或现场交通调查数据。
- 片区质心仅是汇总位置。默认场景仅以 residential/service/unclassified/living_street 本地道路作接入候选。车辆的实际产生/吸引点为邻近、允许小客车且连通外部出入口的路段位置。它不是已核实建筑入口或私人车道，不绘制穿楼行驶。
- SUMO 从相应车道的合法位置安全插入车辆；车道占满时保留等待，不强制插入或瞬移。
- 默认适度演示 5% 初始存量（41 辆）在 t=0 申请出发，合计 50% 存量（418 辆）按早晚高峰三角分布释放；峰值时刻分别为需求窗口的 30% 和 65%。旧网络诊断参数为初始释放 15%、早晚总出发比例 70%/40%，单独保留。
- 内部出发中约 30% 以另一建筑片区为目的地，其余驶向边界；目的地先做真实路网可达性检查。
- 边界流入原有车辆的 ID、时刻和起点保持不变。早高峰约 25%、晚高峰约 55% 的小客车改以内部片区为终点，绝不复制边界来车。
- 到达内部片区后车辆计入停车存量，本模型不再为同一车辆生成第二次行程。

## 先修复网络问题，再观察高峰

新增内部 OD 暴露了原路网在倪家桥路口的短连接问题：两个独立信号节点之间的外部路段仅 0.20m，车辆跨越两节点后形成互相阻塞。即使流量降至 90 辆/小时/入口，仍出现 t≈415 后持续卡死；绿灯正常出现，首车无同车道前车，不能把这种问题当作真实道路容量过载。

新演示明确使用 `joined_nijiaqiao_v1`：只合并这两个紧邻节点并重建该路口冲突几何和实验信号，原 baseline 与正式研究完全保留。此合并是模型拓扑修正假设，不是现场核实的信号设计。

同一 807 个行程 ID、起终点、出发时刻和行为种子的对照：原网完成 513，末尾在网 294/停止 285；新网完成 788，末尾在网 19/停止 1。首堵车辆在新网 t=341s 完成。道路裁切使 21 辆车的接入里程偏移 0.281m，因此完整需求哈希不同，这不是完全相同几何下的政策比较。详见 `docs/evidence/internal_access_diagnostic.json` 和 `internal_access_counterfactual.json`。

默认适度演示保持 160 辆/小时/入口，没有继续压低需求来掩盖互锁。四个场景均有排队与消散，零碰撞/瞬移，未完成车辆仍照实计入。

## 两层守恒

每个积分步同时验证：

1. 已到出发时刻的行程 = 等待插入 + 在网 + 完成。
2. 初始停车存量 + 已插入边界来车 = 当前停车存量 + 当前在网车辆 + 已完成边界离开车辆。

内部等待插入仍属于停车存量；未插入边界来车不属于系统内库存。所有片区库存必须非负。外部交通、内部产生和内部吸引因此不会重复计数。

旧版 `external_waiting` 是所有未插入行程的历史字段；有内部需求时不能把它全部叫作外部等待。新的 `stock_timeseries.json` 分开给出 `boundary_insertion_waiting` 和 `internal_insertion_waiting`。总耗时仍包含所有已到出发时间但尚未成功插入的目标行程。

## 可审计文件

每个新演示回放都有：

- `internal_zones.json`：建筑 OSM ID、片区质心、实际插入道路/位置、初始库存、参数假设、来源与限制。
- `od_matrix.json` / `od_matrix.csv`：起终点、内部/边界类别、300s 时间窗、准确生成行程数。各行数量之和等于完整行程清单，属于具体随机种子的已生成 OD，不冒充观测 OD。
- `stock_timeseries.json`：每 5s 的各片区停车量、在网量、边界累计进出、两种插入等待和守恒残差，另有 t=0 初始状态。
- `signal_topology.json`：真实 SUMO 信号控制器与 controlled-link 索引、入口/出口/内部连接车道。
- `signals.json`：t=0 和每次颜色变化时的 SUMO 实际状态字符串及实际相位。现有 S0 固定时制、S7 协调控制继续运行，没有另造与车辆物理无关的动画灯。
- `queue_hotspots.json`：每 5s 按道路统计速度 <0.1m/s 的真实仿真车辆数。这是停止车辆数量，包含红灯停车、堵塞和安排的临停，不是连续物理排队长度。

信号颜色说明的是本次仿真的真实状态，现场信号配时、转向规则仍待核实。真实 SUMO 数据不等于现场校准数据。

## 重现

```sh
python scripts/restore_assets.py
.venv/bin/python scripts/run_internal_demo.py
```

默认产生 `internal_moderate_{S0,S7}_{am,pm}_42_v1` 四个 1800s 适度演示，并保留一个旧网络 AM S0 诊断回放。`--scenario severe` 可重现旧网络四场诊断；其完整源运行与证据保留，不将四场全部打入网站。需求结束于 1500s，预热 300s。同网络的 S0/S7 在各自时段使用相同需求哈希。脚本先原子构建/校验新路口变体，避免并发读取半写文件。不会覆盖已完成但配置不同的运行，异常中断的目录须先检查并另存。

`npm run dev`、`npm test`、`npm run build` 会先校验演示文件，缺失时生成。轨迹以 1s 抽样发布，仅抽取已有真实状态，不重做物理仿真或改变指标。原始 0.5s 轨迹和完整需求清单保留于本地运行目录。正式研究不参与这一步。
